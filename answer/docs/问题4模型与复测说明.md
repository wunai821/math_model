# 问题4模型与复测说明

## 模型已经统一

`src/q4/model.py` 统一枚举候选和建立资源约束，供正式优化入口 `solve.py`、撤销上限检验 `check_cancel_limit.py` 和复测入口 `reproduce.py` 共用。原始附件为 `附件/附件1.xlsx`，模型不读取提交表来替代求解。

每台装备i的合法操作候选集合为Kᵢ。候选包括不变、频移±10、首次时间平移±5、撤销，以及仅C类允许的间隔变化±10；同一装备至多改变一个参数。每个候选完整展开全部重复使用时段，采用半开区间，剔除频域越界、时间为负或间隔为负的候选。

变量xᵢₖ∈{0,1}表示是否选择候选。约束是：每台恰选一个候选；每个单位时频资源格最多被一个有效候选占用。全部150台装备形成6209个候选和42072条去重资源互斥约束。问题4没有统一结束上限。

正式优化按以下七项目标逐层进行：撤销总数、A类撤销、B类撤销、调整总数、A类调整、B类调整、Σ(|频移|+2|时移|+|间隔变化|)。后一阶段固定前一阶段的已获值；限时可行值不等于已证明最优值。

本轮求解先检查“撤销总数≤3且A类撤销=0”的可行性，再固定撤销总数进行后续优化。这两个附加条件是搜索策略，不是题目新增的物理限制。默认正式优化入口自动读取当前方案；无缓存时读取持久基准。每阶段用已验证方案给出当前目标上界，防止短时求解退化；不固定具体装备的操作。

## 安装与运行位置

以下命令均在项目的 `answer` 目录执行，主项目和队友运行包使用相同目录结构。

```powershell
uv sync --frozen --python 3.13.2
uv run --frozen python src/q4/reproduce.py
```

锁文件指定OR-Tools 9.15.6755和openpyxl 3.1.5。无需Node、Excel应用或现有 `.cache`。输出写入 `.cache/q4/reproduce/solution.json` 和 `verification.json`，不覆盖正式方案与提交表。重复运行请指定新的空目录，例如 `--output .cache/q4/reproduce_second`；非空目录会被拒绝，防止把旧成功文件当成本轮结果。

## 两种复测的含义

### 重建已知指标（默认）

持久基准位于 `benchmarks/q4_reference.json`，不受缓存忽略规则影响。程序先核对原始附件SHA-256、基准统计和全部周期冲突，再从原始附件重新建立完整模型。将目标向量约束为 `(3,0,3,141,18,37,848)`，仅将基准操作作为求解提示，不把具体装备操作固定成约束。

验收条件是求解器实际返回可行解、重新计算的七项目标完全一致，以及独立区间检查冲突数为0。本机本轮约4.3秒完成，装备安排也与基准相同。其他环境只要求指标一致和方案合法，不要求求解日志、运行时间或JSON文件字节一致。

这是已知指标的模型可行性复测，不是从零优化，也不提供新的最优性证明。可行性模型返回OPTIMAL不能解释为原问题的最优撤销数已证明。

### 从原始附件重新搜索

```powershell
uv run --frozen python src/q4/reproduce.py --mode search --seconds 120 --workers 2
```

此模式不读取基准、问题2方案、问题4缓存或提交表，也不固定七项目标向量。仅要求撤销不超过3且A类全保，搜索一个可行方案。本轮72.69秒重新找到 `(3,0,3,147,20,37,983)`，完整区间复核为零冲突；这证明本轮确实从原始附件重新搜索到了核心改进，后五项尚待继续优化。

多线程限时搜索不保证每次都在同一时限内找到相同结果。UNKNOWN返回非零退出码，不产生成功方案；不能据此断言不可行。若需要后续七层优化，在独立候选上继续：

```powershell
Copy-Item .cache/q4/search/solution.json .cache/q4/cold_candidate.json
uv run --frozen python src/q4/solve.py --hint cold_candidate.json --output cold_refined.json --fix-prefix 1 --seconds 10 --workers 3
```

新方案经独立检查和字典序比较后再采纳。普通 `solve.py` 的默认提示会使用持久基准，因此不能把默认运行称为无提示搜索。

## 记录与证明范围

每次复测记录原附件、持久基准（冷搜索为null）、模型文件、复测脚本、依赖锁文件的SHA-256，以及Python/OR-Tools版本、线程数、随机种子、时限、实际目标和独立冲突检查结果。原附件变化、基准损坏或旧输出目录被复用时，程序拒绝继续。

历史撤销下界2保留在正式方案及基准历史记录中；本次复测没有重新证明该下界。`verification.json` 显式记录 `optimality_proved=false`。有限窗口[0,643)只用于问题3，不会被复测程序添加到问题4。


覆盖共享模型、不可避免冲突、单参数限制、历史基准损坏、源附件不一致和旧输出目录误用等情形。正式结果Excel仍用原有导出及独立验证入口生成；复测输出不自动替换正式交付物。
