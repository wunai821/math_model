# 问题2：怎么把冲突“挪开”

## 1. 题目要我们回答什么

问题1找出了297对冲突。本问要为每台装备重新安排一个合法状态，使剩下执行的计划之间不再冲突，同时尽量少撤销、少调整。

可以把每台装备的处理方式理解成三选一：

- 频率整体平移一点；
- 第一次使用时间整体平移一点；
- 直接撤销这台装备。

调整后，频宽、单次时长、使用间隔和使用次数都不能改变。

## 2. 允许怎么调整

对装备 `i` 设置：

- 频移 `u_i`：整数，`-10≤u_i≤10`；
- 首次时间平移 `v_i`：整数，`-5≤v_i≤5`；
- 撤销标记 `z_i`：0表示保留，1表示撤销。

同一台装备最多只做一种调整，所以不能同时频移和时间平移；撤销时两种平移都必须为0。调整后还要满足：

```text
0 ≤ a_i+u_i < b_i+u_i ≤ 100
s_i+v_i ≥ 0
```

第 `k` 次使用的时间区间变为：

```text
[s_i+v_i+k(d_i+g_i), s_i+v_i+k(d_i+g_i)+d_i)
```

本问只使用题目明确给出的“平移幅度”和“首次时间非负”限制，不额外假设一个统一的最后结束时间。

## 3. 冲突约束怎么写

对任意两台没有撤销的装备，至少要满足下面一个条件：

1. 调整后的频段完全分开；或
2. 两台装备的所有重复使用时间区间完全分开。

频段分开可以写成：

```text
b_i+u_i ≤ a_j+u_j
或
b_j+u_j ≤ a_i+u_i
```

时间端点相接是合法的，因为统一使用左闭右开区间。程序会把每台装备的全部重复时段都展开，再检查调整后可能新出现的冲突，而不是只检查问题1中已经发现的冲突。

为减少模型规模，程序预先计算每对装备的相对时间平移 `v_i-v_j` 哪些取值是安全的，再把“所有重复时间不冲突”压缩成一个允许取值集合。另有一个枚举候选的网格模型作为交叉参考；两种模型采用同样的题目约束。

## 4. 多目标怎么处理

题目没有给出数值权重，因此采用容易解释的“先后顺序”优化，也叫字典序优化：

1. 先让撤销总数尽可能少；
2. 在此基础上，让A类撤销尽可能少；
3. 再让B类撤销尽可能少；
4. 再让调整总数尽可能少；
5. 再分别减少A类、B类调整数；
6. 最后减少平移幅度。

最后一项使用 `Σ(|u_i|+2|v_i|)`。时间平移的最大允许幅度是5，频移的最大允许幅度是10，所以乘2后两类幅度处于可比较尺度；它等于归一化幅度和的10倍。

每完成一层，就把这一层的结果锁住，再进入下一层。限时阶段如果只找到可行方案，就保留“当前值、下界和状态”，不把 `FEASIBLE` 说成全局最优。

## 5. 最终方案

| 类别 | 原样保留 | 调整 | 撤销 |
|---|---:|---:|---:|
| A类 | 4 | 16 | 0 |

| C类 | 12 | 76 | 2 |
| **合计** | **18** | **126** | **6** |

因此最终执行 `18+126=144` 项计划。126项调整中：频段平移91项，首次时间平移35项。

## 7. 专业解题流程（可直接写进论文）

1. **数据整理**：读取150项原始计划，计算每台装备的重复使用区间。
2. **变量设计**：为每台装备设置频移、时间平移和撤销变量。
3. **合法性约束**：限制平移幅度、频段边界、首次时间非负，并保证“一台装备最多一种操作”。
4. **冲突约束**：对所有装备对检查调整后的频段和全部重复时间区间。
5. **分层优化**：按撤销数、类别撤销数、调整数、调整幅度依次求解。
6. **独立复核**：不用求解器内部判断，重新展开所有区间，检查零冲突和模板填写是否正确。

## 9. 一句话结论

问题2用“尽量少撤销、再尽量少调整”的顺序，把297对冲突全部消掉：撤销6项、调整126项、保留18项，最终144项计划可以同时执行。

## 10. 源码解读：模型如何把“挪开”写成约束

问题2主要由 `src/q2/solve_compact.py` 和 `src/q2/solve.py` 完成。前者负责紧凑的CP-SAT模型，后者提供原始计划读取和参考网格模型；`src/q2/verify.py` 完全独立地检查最终方案。

### 10.1 `safe_differences`：先算出哪些相对时间差安全

源码先把两台装备所有可能的相对时间平移 `d=-10,...,10` 逐一试一遍：

```python
for d in range(-10, 11):
    overlap = any(
        sa + d < eb and sb < ea + d
        for sa, ea in intervals(a)
        for sb, eb in intervals(b)
    )
    if not overlap:
        result.append(d)
```

如果某个 `d` 让全部重复时段都不重叠，就把它放进安全集合。这样求解时不用反复展开所有时间区间，只需要判断 `v_i-v_j` 是否属于这个集合。

### 10.2 `add_allowed_assignments`：限制一台装备只能做一种操作

源码用允许组合表表达“原样、只频移、只时间平移”三种情况：

```python
model.add_allowed_assignments(
    [f, t, changed],
    [(0, 0, 0)]
    + [(x, 0, 1) for x in fv if x]
    + [(0, x, 1) for x in tv if x]
)
```

表中没有 `(非零频移, 非零时间平移, 1)`，所以模型天然禁止两种平移同时发生。撤销变量为真时，代码还强制 `f=t=changed=0`。

### 10.3 `model.add_bool_or`：给每一对装备至少留一条避让路

对一对可能冲突的装备，源码把“撤销、频段在前、频段在后、时间安全”放进同一个或约束：

```python
terms = [cancel_i, cancel_j, i_before_j, j_before_i]
if safe:
    terms.append(time_safe)
model.add_bool_or(terms)
```

这句话的意思是：两台装备不能同时占用同一块资源，但不要求所有装备都必须改频率。只要撤销一台、频段分开，或者重复时间完全错开，冲突就被消除了。

### 10.4 七层目标如何落到代码

源码把目标按顺序放入 `objectives` 列表：

```python
cancel_total → cancel_A → cancel_B →
adjust_total → adjust_A → adjust_B → shift_cost
```

每完成一层，就执行 `model.add(expr == value)` 锁定当前结果，再求下一层。每个阶段都把状态、当前值和下界写入 `solution.json`，因此文档可以区分 `OPTIMAL` 和 `FEASIBLE`，不会把限时可行解误写成全局最优。

最后，`save(...)` 将每台装备的 `df`、`dt`、`canceled` 转成完整方案和附件2需要的行；`verify.py` 再重新计算区间和冲突，不依赖模型内部的候选占用表。
