# 问题4：C类装备还能改变使用间隔

## 1. 题目要我们回答什么

问题2只能挪频率或挪首次时间。本问进一步放宽：C类装备还可以改变“两次使用之间的间隔”，看看能不能用更灵活的方式消除冲突。

本问从附件1的150项原始计划重新开始，**不把问题2的方案固定下来**。目标仍是先少撤销，再少调整，最后尽量少改动幅度。

## 2. 每台装备可以做什么

设：

- `u_i`：频率平移，范围 `[-10,10]`；
- `v_i`：首次时间平移，范围 `[-5,5]`；
- `h_i`：间隔变化，范围 `[-10,10]`，仅C类可用；
- `z_i`：撤销标记。

一台装备最多选择一种操作：频移、首次时间平移、间隔调整或撤销。也就是说，不能一边改频率、一边改时间，还同时改间隔；撤销时三个调整量都必须为0。

调整后必须满足：

```text
0 ≤ a_i+u_i < b_i+u_i ≤ 100
s_i+v_i ≥ 0
g_i+h_i ≥ 0
```

频宽、单次使用时长和使用次数始终不变；A、B类装备的间隔不允许改变。

第 `k` 次使用区间为：

```text
[s_i+v_i+k(d_i+g_i+h_i),
 e_i+v_i+k(d_i+g_i+h_i))
```

其中 `d_i=e_i-s_i`。当间隔变化为负数时，后续时段会逐次提前；因此程序必须展开全部重复时段，不能只看第一次使用。

## 3. 一个重要的边界说明

问题4沿用题目明确给出的非负起点和调整幅度限制，**没有额外设置统一的最后结束时间**。问题3为了计算新增容量，另行假设了 `[0,643)` 时间窗口；这个窗口不能自动套到问题4。

因此，当前问题4方案中出现最后结束时刻超过643甚至超过650的装备，并不违反当前问题4模型。若论文决定把问题4也限制在 `[0,H)`，必须同时修改求解器和独立验证器后重新求解，不能只在结果表里补一个时间上限。

## 4. 如何建立优化模型

程序为每台装备枚举所有合法候选状态：原样保留、频移、首次时间平移、（C类）间隔调整和撤销。每台装备必须且只能选择一个候选。

对每个候选完整展开所有重复时间区间，并建立“每个单位时频格最多由一个候选占用”的约束。这样既能检查原始冲突，也能检查调整后新产生的冲突；左闭右开端点相接合法。

为了交叉复核，项目还实现了一个紧凑模型：把首次时间平移和间隔变化列成离散模式，并预先计算每对装备哪些模式组合不会冲突。网格模型和紧凑模型允许的操作完全相同，结果可以互相比较。

本次网格模型规模为 **6209个候选**、**42072条去重资源约束**。最终提交方案由网格模型产生，随后由独立验证程序重新读取原始数据并检查。

## 5. 多目标顺序

为了与问题2保持可比，按以下顺序优化：

1. 撤销总数最少；
2. A类撤销最少；
3. B类撤销最少；
4. 调整总数最少；
5. A类调整最少；
6. B类调整最少；
7. 调整幅度最小。

最后一层成本为：

```text
Σ(|u_i| + 2|v_i| + |h_i|)
```

它是归一化幅度 `Σ(|u_i|/10 + |v_i|/5 + |h_i|/10)` 的10倍。间隔变化引起的后续累计时间移动已经体现在冲突检查中，不再重复计费。

## 6. 当前结果

| 类别 | 原样保留 | 调整 | 撤销 |
|---|---:|---:|---:|
| A类 | 2 | 18 | 0 |
| B类 | 0 | 37 | 3 |
| C类 | 4 | 86 | 0 |
| **合计** | **6** | **141** | **3** |

最终执行 `6+141=147` 项计划，独立验证冲突装备对数为 **0**。

调整方式统计：

- 频移57项；
- 首次时间平移37项；
- C类间隔调整47项。

撤销装备为：`B021、B029、B033`。

当前方案的幅度分解为 `Σ|u|=370`、`Σ|v|=111`、`Σ|h|=256`，求解器记录的归一化成本 `10D=848`。

## 7. 最优性应该怎样表述

当前撤销数为3。通过历次等价模型和独立比较，已知撤销总数至少为2，因此当前结果是一个**零冲突可行解**，但还没有证明3就是全局最少。

求解日志中的阶段状态如下：

| 目标 | 当前值 | 日志下界 | 状态 |
|---|---:|---:|---|
| 撤销总数 | 3 | 0 | FEASIBLE |
| A类撤销数 | 0 | 0 | OPTIMAL |
| B类撤销数 | 3 | 0 | FEASIBLE |
| 调整总数 | 141 | 46 | FEASIBLE |
| A类调整数 | 18 | 7 | FEASIBLE |
| B类调整数 | 37 | 33 | FEASIBLE |
| 归一化调整成本 | 848 | 211 | FEASIBLE |

这里要区分两件事：表中的“日志下界”是某一阶段、在前序目标锁定条件下求解器当时给出的界；“已知撤销下界2”来自独立的等价模型比较。最稳妥的结论是：**当前方案可行、零冲突，但整套问题4方案尚未证明为字典序全局最优。**

## 8. 专业解题流程（通俗版）

1. **从原始数据重新开始**，不直接照搬问题2的调整。
2. **生成合法候选**：保留、频移、时间平移、C类间隔调整、撤销。
3. **过滤明显非法候选**：频段越界、首次时间为负、C类间隔变负、同时做多种调整。
4. **建立冲突约束**：展开全部重复时段，保证任意两个执行候选不占同一时频资源。
5. **按七层目标求解**：先保留更多装备，再减少调整和幅度。
6. **用独立验证器复核**：重新读取附件、检查权限和边界、逐对检查所有重复区间、核对Excel字段。

## 10. 一句话结论

允许C类改变使用间隔后，可以保留147项计划并做到零冲突；当前撤销3项，已知理论下界为2，结果是可靠可行解，但不能写成已经证明的全局最优解。

## 模型作用与完整步骤（详细版）

### 这个模型和问题2有什么根本区别

问题2中，一台装备只有“改频率、改首次时间、撤销”几种选择；问题4增加了C类的“改间隔”选择。改间隔不是只改变第二次使用，它会影响第二次、第三次直到最后一次使用的位置：

```text
第k次开始时间 = 首次时间 + k × (单次时长 + 原间隔 + 间隔变化)
```

因此，问题4不能只在问题2结果上补一列`新间隔`，而必须从原始计划重新建立全部候选，并重新检查所有重复时段。模型的核心作用就是在扩大操作范围后，寻找一套仍然没有冲突的完整方案。

### 为什么采用“候选状态”而不是只设三个连续变量

如果只写`u、v、h`三个变量，容易忘记“最多只能改一个参数”的组合限制。源码把每一种合法操作预先列成候选状态，例如：

```text
(0,0,0)       原样保留
(+3,0,0)      只频移3格
(0,-2,0)      只把首次时间提前2格
(0,0,+4)      C类只把间隔增加4格
(0,0,0,cancel) 撤销
```

然后要求每台装备恰好选择一个候选。这样，非法组合在进入优化器前就已经被排除，模型更容易解释和验证。

### 候选生成、资源约束和目标之间的关系

| 步骤 | 模型动作 | 解决的实际问题 |
|---|---|---|
| 1 | `candidates_for(p)`生成候选 | 列出这台装备所有允许的操作 |
| 2 | 检查频段、时间和间隔边界 | 删除不可执行的候选 |
| 3 | `add_exactly_one` | 保证每台装备只能有一个最终状态 |
| 4 | 展开候选的全部重复时段 | 发现改间隔造成的后续新冲突 |
| 5 | `add_at_most_one` | 同一时频格不能被两台执行装备占用 |
| 6 | 七层目标逐层求解 | 在可行方案中按题意择优 |

### 为什么需要网格模型和紧凑模型两套写法

网格模型把候选占用的整数时频格直接列出来，直观、容易核查，适合做最终验证；紧凑模型把重复时间模式压缩成安全组合，规模更小，适合快速复测和比较。

两套模型都必须遵守同样的题目规则：

- 频率只能平移`[-10,10]`；
- 首次时间只能平移`[-5,5]`；
- 只有C类能改间隔`[-10,10]`，且新间隔不能为负；
- 一台装备不能同时做两种调整；
- 所有重复使用时段必须没有冲突。

如果两套模型得到不同结果，应先检查边界、区间端点和参数权限，而不是直接选择数量较大的结果。

### 从输入到当前方案的完整步骤

1. **读取原始附件**，不直接沿用问题2的变量结果。
2. **为每台装备生成候选状态**，C类比A/B类多一组间隔变化候选。
3. **过滤非法状态**，包括频段越界、首次时间为负、间隔为负和多参数同时变化。
4. **建立每台装备的恰选约束**，保证输出中不会出现一台装备同时有两种操作。
5. **展开所有候选的全部重复时间**，建立时频资源互斥约束。
6. **按七层目标求解**：先少撤销，再少调整，最后少改动幅度。
7. **保存每一阶段的当前值、下界和状态**，便于判断哪些结论已经证明。
8. **用独立验证器复核**，重新从附件计算全部区间，不调用模型内部候选表。
9. **生成报告和Excel**，并保留q4缓存，支持网格模型、紧凑模型和复测脚本之间的比较。

### 为什么当前结果不能直接写成“最优”

当前方案撤销3项，已知下界为2。下界只说明“至少需要撤销2项”，而当前方案说明“撤销3项可以做到零冲突”；两者不相等，所以还不能证明3是最少。

同理，后续调整数量和调整幅度虽然已经有可行值和求解器下界，但只要状态是`FEASIBLE`，就应写成“当前可行结果”，不能写成“已经达到全局最优”。这正是模型日志和独立验证都要保留下来的原因。

## 11. 源码解读：如何把C类间隔调整加入模型

问题4的关键源码分工是：`src/q4/model.py` 生成合法候选并建立资源约束，`src/q4/solve.py` 按七层目标求解，`src/q4/verify.py` 独立验算，`src/q4/reproduce.py` 用于复测。

### 11.1 `candidates_for`：把每台装备的合法操作列出来

源码先放入原样候选，再加入频移和首次时间平移；只有编号以C开头的装备才额外加入间隔变化：

```python
moves = [(0, 0, 0)]
moves += [(x, 0, 0) for x in range(-10, 11) if x]
moves += [(0, x, 0) for x in range(-5, 6) if x]
if p['id'].startswith('C'):
    moves += [(0, 0, x) for x in range(-10, 11) if x]
```

三元组依次表示 `(频移, 首次时间平移, 间隔变化)`。因为每次只改变一个位置，所以代码层面已经保证了“不能同时改多个参数”。随后还会过滤频段越界、首次时间为负和间隔变负的候选，并额外加入撤销候选。

### 11.2 `build_model`：保证每台装备恰好选一个状态

对每台装备，源码把它的所有候选放进 `indices`，然后写入：

```python
model.add_exactly_one(variables[index] for index in indices)
```

这对应题目中的“保留、调整或撤销三选一”。对于没有撤销的候选，代码再把它占用的每个时频格登记到 `resource` 字典；同一格出现多个候选时，建立：

```python
model.add_at_most_one(variables[index] for index in indices)
```

这条约束负责消除原始冲突和调整后新产生的冲突。

### 11.3 `solve.py`：按七层目标逐层锁定

求解器把每个候选对七个目标的贡献写成：撤销、A类撤销、B类撤销、调整、A类调整、B类调整和幅度成本。每轮求出一个目标值后，源码用：

```python
model.add(expressions[index] == record['value'])
```

锁住这一轮，再进入下一轮。这样就实现了“先少撤销，再少调整”的字典序，而不是把几个指标随意混成一个权重。

### 11.4 为什么还要有独立验证和复测脚本

`verify.py` 不调用候选生成和资源约束函数，而是重新读取原始附件，检查操作权限、幅度、间隔非负、频段边界和全部重复时段冲突。`reproduce.py` 则从指定基准重新构建约束，可用于确认当前结果不是因为缓存文件或手工表格造成的。

因此，源码链路可以概括为：

```text
附件1.xlsx
   ↓
model.py 生成候选和约束
   ↓
solve.py 求解并写入 .cache/q4/solution.json
   ↓
verify.py 独立验算
   ↓
report.py / export_xlsx.py 生成说明和提交表
```
