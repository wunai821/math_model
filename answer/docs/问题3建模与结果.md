# 问题3：固定问题2后还能增加多少台C类装备

## 1. 题目要我们回答什么

问题2已经给出一套没有冲突的执行方案。本问不再修改问题2的装备，而是在这套方案占用的资源之外，寻找尽可能多的新C类装备位置。

换句话说：**先把问题2的安排“冻结”，再看剩余的频率和时间空位最多能放下多少台相同规格的C类装备。**

## 2. 本问采用的边界和需求

原题只说“不增加时频资源”，没有直接给出时间轴右端点。为了把问题变成一个明确、可复核的容量问题，本项目采用以下建模假设：

- 频率窗口：`[0,100)`；
- 时间窗口：`[0,643)`；
- 643取自原始计划最后一次使用结束时刻的最大值；
- 问题2中已经撤销的计划不占资源，其余有效计划全部固定；
- 新增C类装备统一使用附件1中C类需求：频宽3、单次时长2、间隔8、共使用12次。

因此，这个“142台”的结论只针对上述窗口和固定的q2方案。如果更换时间窗口，或允许重新调整问题2方案，就必须重新求解。

## 3. 一台新增装备有哪些候选位置

设新增装备的频段起点为 `f`，首次使用时间起点为 `s`。为了不越过资源窗口：

```text
f = 0,1,...,97
s = 0,1,...,531
```

每个候选位置的频段为 `[f,f+3)`，第 `k` 次使用时间为：

```text
[s+10k, s+10k+2),  k = 0,1,...,11
```

最后一次使用结束于 `s+112`，所以 `s≤531` 正好保证最后一次结束不超过643。所有区间仍采用左闭右开规则，端点相接不算冲突。

## 4. 怎么从候选位置中选出最多的装备

程序先完整枚举所有可能的 `(f,s)`，再删除与固定q2方案冲突的候选，剩下 **2314** 个候选。

对每个候选设置一个0/1变量 `x_c`：选中为1，不选为0。每个离散的“频率格×时间格”最多只能被一个候选占用，因此模型是：

```text
最大化：选中的候选数量
约束：每个时频格最多被一个候选使用
```

由于所有边界和长度都是整数，单位网格占用与区间不重叠是等价的，不会因为离散化漏掉端点冲突。模型不是按空闲面积估算，而是把全部候选一次性放入优化器，求得真正的最大数量。

模型规模如下：

| 项目 | 数值 |
|---|---:|
| 与q2方案核对后保留的候选位置 | 2314 |
| 去重后的资源排斥约束 | 7217 |
| 原方案占用的时频格 | 15816 |
| 每台新增装备占用的时频格 | 72 |
| 仅按面积得到的宽松上界 | 673 |

面积上界673只是一个很松的参考，真正的上界来自完整的候选冲突模型。

## 5. 求解结果

| 项目 | 结果 |
|---|---:|
| 最大新增C类装备数 | **142** |
| 求解器上界 | **142** |
| 求解状态 | **OPTIMAL** |
| 求解时间（不含建模） | 0.117秒 |
| 工作线程数 | 3 |

因为“当前找到的数量”和“理论上不可能超过的上界”都等于142，所以在本问明确的窗口、需求和固定q2方案下，**142已经证明是最大值**。

## 6. 专业解题流程（通俗版）

1. **冻结基准**：读取问题2完整方案，确认其版本和哈希一致。
2. **确定边界**：使用频率 `[0,100)` 和时间 `[0,643)`。
3. **生成候选**：枚举每个可能的频率起点和首次时间起点。
4. **筛掉冲突**：删除与原有有效计划冲突的候选。
5. **处理候选之间的冲突**：同一时频格不能被两个新增候选同时占用。
6. **最大化数量**：用0/1整数规划一次性选择最多候选。
7. **独立验证**：重新展开每台新增装备的12次使用，逐对检查原有计划、新增计划以及新增计划之间是否冲突。

## 8. 一句话结论

在不扩大 `[0,100)×[0,643)` 资源窗口、并且完全固定问题2方案的前提下，最多还能安排 **142台** 新C类装备，且这个数量已由完整整数模型证明为最大值。

## 模型作用与完整步骤（详细版）

### 这个模型到底解决什么问题

问题3不是重新做问题2，也不是简单数一数剩余空白面积。新装备有12次周期性使用，一台新增装备只要有一次使用和已有计划或另一台新增装备重叠，就不能放置。

因此，本问模型的作用是：

1. 把每一个可能的新增位置看成一个“候选”；
2. 判断候选是否撞到固定的问题2方案；
3. 判断不同新增候选之间是否互相撞车；
4. 从所有不冲突候选中选出最多的候选。

这类模型可以理解为“从很多互相打架的候选中选最多个”，而不是按空闲面积做粗略估算。

### 一台候选为什么由两个数字决定

由于新增C类装备的规格统一，候选只需要确定：

- 频率起点`f`：决定频段`[f,f+3)`；
- 首次时间起点`s`：决定第1次使用`[s,s+2)`。

之后的11次使用由间隔8自动确定：`[s+10k,s+10k+2)`。所以一台新增装备的完整占用可以用一个`(f,s)`位置表示，但冲突检查必须使用它展开后的72个时频格。

### 为什么先固定问题2方案

题目要求“在问题2基础上增加”。如果允许同时调整问题2装备，就会把问题2和问题3混成另一个联合优化问题，142这个数字也不再对应当前题意。

程序因此先做三项基准检查：

- q2方案的150个装备编号必须和附件1完全一致；
- q2有效计划必须在`[0,100)×[0,643)`窗口内；
- q2有效计划之间必须已经没有资源重叠。

只有通过这三项检查，q2的占用资源才会被加入`occupied`，作为新增候选的固定障碍。

### 候选选择模型中每条约束的作用

设候选位置为`c`，二元变量`x_c=1`表示选择它，`x_c=0`表示不选它。

| 模型内容 | 数学/代码表达 | 作用 |
|---|---|---|
| 候选合法 | `f`和`s`在枚举范围内 | 不越过频率和时间窗口 |
| 不撞q2 | `occupied.isdisjoint(cells(c))` | 新装备不能占用原方案资源 |
| 新增之间不撞 | `add_at_most_one` | 同一时频格最多选一个候选 |
| 尽量多 | `maximize(sum(x_c))` | 直接最大化新增装备台数 |

由于所有端点是整数，整数网格中的“同一格不重复占用”与半开区间不重叠完全一致；因此没有用面积近似代替真实冲突。

### 从输入到“142”的完整步骤

1. **读取附件1**，提取C类统一的频宽、时长、间隔和次数。
2. **读取并核对q2方案**，将所有未撤销计划展开成已占用时频格。
3. **计算新增装备跨度**：12次、每次时长2、间隔8，最后一次结束时间为`s+112`。
4. **完整枚举候选**：遍历所有合法`f`和`s`，不是只挑几个空白区域。
5. **删除与q2相撞的候选**，得到2314个可选位置。
6. **建立候选之间的互斥约束**，处理新增—新增冲突。
7. **运行整数规划**，最大化被选候选数量。
8. **检查上界和最优状态**：当前值142、求解器上界142且状态OPTIMAL。
9. **独立复核**：重新展开每台新增装备12次使用，逐对检查所有冲突并核对result3.xlsx。

### 为什么142可以写成“最大值”

“找到142台”只能说明至少有142台可行；只有当求解器同时给出上界142时，才说明任何合法方案都不可能超过142。本问的当前值和上界相等，因此在已经声明的窗口、q2基准和C类需求下，142是被模型证明的最大值。

## 9. 源码解读：如何枚举和选择新增位置

问题3的主程序是 `src/q3/solve.py`，验证入口是 `src/q3/verify.py`，报告由 `src/report_schedule.py` 生成。代码执行顺序与论文流程一一对应。

### 9.1 先从附件中确认C类统一需求

源码不会手工写死某一台C类装备的参数，而是先读取所有C类计划并检查它们是否只有一种规格：

```python
shapes = {
    (p['hi'] - p['lo'], p['end'] - p['start'], p['gap'], p['count'])
    for p in source if p['id'].startswith('C')
}
if len(shapes) != 1:
    raise ValueError('Q3 requires a specified homogeneous C equipment profile')
```

这一步保证新增装备确实使用附件中C类的统一“频宽、时长、间隔、次数”，而不是凭经验填参数。

### 9.2 固定问题2方案并建立已占用资源

程序读取 `.cache/q2/solution.json`，核对装备编号集合和q2基准哈希；撤销计划跳过，其余计划通过 `cells(p)` 展开为已占用的整数时频格：

```python
occupied = set()
for p in q2['plans']:
    if p['canceled']:
        continue
    pcells = set(cells(p))
    if occupied.intersection(pcells):
        raise ValueError('Q2 baseline contains conflicts')
    occupied.update(pcells)
```

这段代码说明 q2 方案不是“只读一个数量”，而是整套频段和全部重复时段都被冻结为新增装备的障碍。

### 9.3 枚举所有新增候选，再过滤冲突

候选生成的核心是两个循环：一个枚举首次时间，一个枚举频率起点。每个候选生成12次使用的全部时频格；只要与 `occupied` 没有交集，才加入模型：

```python
for start in range(horizon - span + 1):
    for lo in range(101 - width):
        p = make_candidate(start, lo, width, duration, gap, count)
        if occupied.isdisjoint(cells(p)):
            candidates.append(p)
```

所以“2314个候选”不是抽样结果，而是从全部整数起点完整枚举并筛选后的数量。

### 9.4 用资源互斥约束最大化数量

一个整数时频格如果被多个候选使用，源码把这些候选放入同一个 `add_at_most_one` 约束；最后最大化所有候选变量之和：

```python
for ids in exclusions:
    model.add_at_most_one(variables[i] for i in ids)
model.maximize(sum(variables))
```

这就是“同一块资源只能放一台新增装备”。求解结束后，`verify.py` 会重新展开新增装备和原有计划的区间，独立确认冲突数为0。

## 进一步拆解：一个新增候选是怎样被判定和选择的

### 先把“新增一台”写成一个完整对象

新增装备的表面记录只有频段和首次时间，但模型内部会把它展开为12个时间区间，再进一步展开为72个整数时频格：

```text
频率格数 = 3
每次使用时间格数 = 2
使用次数 = 12
总占用格数 = 3 × 2 × 12 = 72
```

这说明为什么不能只看一台候选的第一行Excel记录：第一行只写首次使用区间，后面11次使用同样会占资源。

### 候选范围是怎样算出来的

频率窗口是`[0,100)`，候选频宽为3，所以频率起点必须满足：

```text
0 ≤ f ≤ 100-3 = 97
```

一次使用时长为2、间隔为8，因此相邻两次开始时间相差10；12次使用的最后一次结束于：

```text
s + 11×10 + 2 = s + 112
```

为了让最后结束时间不超过643：

```text
s + 112 ≤ 643  →  0 ≤ s ≤ 531
```

所以程序枚举`f=0,...,97`和`s=0,...,531`，理论上有`98×532=52136`个起点组合，再剔除与q2资源重叠的位置，最终保留2314个候选。

### `cells`为什么能代替复杂的区间公式

源码中的`cells(p)`把一台计划在每个重复时段占用的频率格和时间格写成集合。例如频段`[10,13)`、时间`[4,6)`会占用：

```text
(时间4,频率10)、(时间4,频率11)、(时间4,频率12)
(时间5,频率10)、(时间5,频率11)、(时间5,频率12)
```

两台计划的这些集合有交集，当且仅当它们在整数网格上有资源重叠。`occupied.isdisjoint(...)`用于比较新增候选和q2基准，`add_at_most_one(...)`用于比较新增候选之间。

### 面积上界为什么只是辅助信息

程序还计算：

```text
可用总面积 ÷ 一台新增装备占用面积
```

得到673台的宽松上界。这个上界假设所有空闲格都能被完美拼接，但周期性时间结构通常做不到；因此673不能当作答案。CP-SAT真正使用的是每个候选之间的互斥约束，只有求解器上界也等于142，才能证明142是最大值。

### 结果如何写入Excel

求解器选中的候选会重新编号为1、2、3……，每台新增装备输出：

- 装备编号；
- 频段`[lo,hi)`；
- 首次时间`[start,end)`。

验证器不会假设“编号连续就一定正确”，而是检查每行参数、重复12次的时间、窗口和所有冲突。导出程序再把这些行按附件2的表头写入`result3.xlsx`。
