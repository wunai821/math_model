# 问题3：固定问题2后还能增加多少台C类装备

## 1. 题目要我们回答什么

问题2已经给出一套没有冲突的执行方案。本问不再修改问题2的装备，而是在这套方案占用的资源之外，寻找尽可能多的新C类装备位置。

换句话说：**先把问题2的安排“冻结”，再看剩余的频率和时间空位最多能放下多少台相同规格的C类装备。**

## 2. 本问采用的边界和需求

原题只说“不增加时频资源”，没有直接给出时间轴右端点。为了把问题变成一个明确、可复核的容量问题，本项目采用以下建模假设：

- 频率窗口：`[0,100)`；
- 时间窗口：`[0,643)`；
- 643取自原始计划最后一次使用结束时刻的最大值；
- 问题2中已经撤销的计划不占资源，其余有效计划全部固定；
- 新增C类装备统一使用附件1中C类需求：频宽3、单次时长2、间隔8、共使用12次。

因此，这个“142台”的结论只针对上述窗口和固定的q2方案。如果更换时间窗口，或允许重新调整问题2方案，就必须重新求解。

## 3. 一台新增装备有哪些候选位置

设新增装备的频段起点为 `f`，首次使用时间起点为 `s`。为了不越过资源窗口：

```text
f = 0,1,...,97
s = 0,1,...,531
```

每个候选位置的频段为 `[f,f+3)`，第 `k` 次使用时间为：

```text
[s+10k, s+10k+2),  k = 0,1,...,11
```

最后一次使用结束于 `s+112`，所以 `s≤531` 正好保证最后一次结束不超过643。所有区间仍采用左闭右开规则，端点相接不算冲突。

## 4. 怎么从候选位置中选出最多的装备

程序先完整枚举所有可能的 `(f,s)`，再删除与固定q2方案冲突的候选，剩下 **2314** 个候选。

对每个候选设置一个0/1变量 `x_c`：选中为1，不选为0。每个离散的“频率格×时间格”最多只能被一个候选占用，因此模型是：

```text
最大化：选中的候选数量
约束：每个时频格最多被一个候选使用
```

由于所有边界和长度都是整数，单位网格占用与区间不重叠是等价的，不会因为离散化漏掉端点冲突。模型不是按空闲面积估算，而是把全部候选一次性放入优化器，求得真正的最大数量。

模型规模如下：

| 项目 | 数值 |
|---|---:|
| 与q2方案核对后保留的候选位置 | 2314 |
| 去重后的资源排斥约束 | 7217 |
| 原方案占用的时频格 | 15816 |
| 每台新增装备占用的时频格 | 72 |
| 仅按面积得到的宽松上界 | 673 |

面积上界673只是一个很松的参考，真正的上界来自完整的候选冲突模型。

## 5. 求解结果

| 项目 | 结果 |
|---|---:|
| 最大新增C类装备数 | **142** |
| 求解器上界 | **142** |
| 求解状态 | **OPTIMAL** |
| 求解时间（不含建模） | 0.117秒 |
| 工作线程数 | 3 |

因为“当前找到的数量”和“理论上不可能超过的上界”都等于142，所以在本问明确的窗口、需求和固定q2方案下，**142已经证明是最大值**。

## 6. 专业解题流程（通俗版）

1. **冻结基准**：读取问题2完整方案，确认其版本和哈希一致。
2. **确定边界**：使用频率 `[0,100)` 和时间 `[0,643)`。
3. **生成候选**：枚举每个可能的频率起点和首次时间起点。
4. **筛掉冲突**：删除与原有有效计划冲突的候选。
5. **处理候选之间的冲突**：同一时频格不能被两个新增候选同时占用。
6. **最大化数量**：用0/1整数规划一次性选择最多候选。
7. **独立验证**：重新展开每台新增装备的12次使用，逐对检查原有计划、新增计划以及新增计划之间是否冲突。

## 9. 源码解读：如何枚举和选择新增位置

问题3的主程序是 `src/q3/solve.py`，验证入口是 `src/q3/verify.py`，报告由 `src/report_schedule.py` 生成。代码执行顺序与论文流程一一对应。

### 9.1 先从附件中确认C类统一需求

源码不会手工写死某一台C类装备的参数，而是先读取所有C类计划并检查它们是否只有一种规格：

```python
shapes = {
    (p['hi'] - p['lo'], p['end'] - p['start'], p['gap'], p['count'])
    for p in source if p['id'].startswith('C')
}
if len(shapes) != 1:
    raise ValueError('Q3 requires a specified homogeneous C equipment profile')
```

这一步保证新增装备确实使用附件中C类的统一“频宽、时长、间隔、次数”，而不是凭经验填参数。

### 9.2 固定问题2方案并建立已占用资源

程序读取 `.cache/q2/solution.json`，核对装备编号集合和q2基准哈希；撤销计划跳过，其余计划通过 `cells(p)` 展开为已占用的整数时频格：

```python
occupied = set()
for p in q2['plans']:
    if p['canceled']:
        continue
    pcells = set(cells(p))
    if occupied.intersection(pcells):
        raise ValueError('Q2 baseline contains conflicts')
    occupied.update(pcells)
```

这段代码说明 q2 方案不是“只读一个数量”，而是整套频段和全部重复时段都被冻结为新增装备的障碍。

### 9.3 枚举所有新增候选，再过滤冲突

候选生成的核心是两个循环：一个枚举首次时间，一个枚举频率起点。每个候选生成12次使用的全部时频格；只要与 `occupied` 没有交集，才加入模型：

```python
for start in range(horizon - span + 1):
    for lo in range(101 - width):
        p = make_candidate(start, lo, width, duration, gap, count)
        if occupied.isdisjoint(cells(p)):
            candidates.append(p)
```

所以“2314个候选”不是抽样结果，而是从全部整数起点完整枚举并筛选后的数量。

### 9.4 用资源互斥约束最大化数量

一个整数时频格如果被多个候选使用，源码把这些候选放入同一个 `add_at_most_one` 约束；最后最大化所有候选变量之和：

```python
for ids in exclusions:
    model.add_at_most_one(variables[i] for i in ids)
model.maximize(sum(variables))
```

这就是“同一块资源只能放一台新增装备”。求解结束后，`verify.py` 会重新展开新增装备和原有计划的区间，独立确认冲突数为0。
